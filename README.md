## Telemetry convention (adopt in every new skill)

Each skill ships `tests/run_tests.py` with:
- deterministic fixture tests (stdlib-only where possible),
- `--model <id> [--auto]`: run + append one JSON line to
  `~/.claude/skills/telemetry/<skill>.jsonl`; `--auto` self-limits to 8
  recorded runs per (model, skill version) then becomes a no-op,
- `--report`: model x skill-version matrix (runs, pass rate, duration mean+/-SD).

SKILL.md rule 0 tells Claude to call `--auto` once per session with its own
model id. Result: as new models are used, the regression matrix fills itself.
The telemetry/ ledger directory is committed too — it IS the data.

## Wrapping third-party upstreams (adopt when a skill depends on someone else's release)

`codex-security-scan` drives OpenAI's Apache-2.0
[codex-security](https://github.com/openai/codex-security) without vendoring a
single line of it: the package is installed from npm into a cache at runtime,
so upstream's improvements arrive on their own. The maintenance deal is
enforced by CI, not by anyone watching a changelog:

- `UPSTREAM_PIN` holds an exact known-good version — users always install that,
  so an upstream release can never break someone mid-scan.
- `tests/contract_test.py` asserts every assumption the skill makes about
  upstream (skill files, prompt-only fallback, workbench subcommands, schema
  enums, offline-ness) and runs a full scan lifecycle end to end.
- `.github/workflows/upstream-drift.yml` runs that weekly against `@latest`:
  contract holds and upstream moved → **PR** bumping the pin; contract breaks →
  **issue** naming the broken assumption. Either way a human decides.
